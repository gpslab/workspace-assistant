Workspace Assistant

A Telegram bot that runs Claude Code in your git repository, commits the result and drives epics of tasks from design to merged pull requests.

Install GitHub

A knowledge base you edit from your phone

The bot works in a git repository of documents, the managed repository: notes, decisions, plans, task texts. You write to the bot in Telegram; the message goes to claude -p in the context of that repository, the changes are committed and pushed automatically (unless AUTO_COMMIT=0), and the reply links to the commit.

Telegram ↔ bot ↔ claude -p ↔ git push

It is meant for documents, not for a code base: nothing is reviewed before a push. Code lives in separate repositories, and changes there go through pull requests.

⚠️ Read this before you start the bot

  • By default the bot starts Claude with --dangerously-skip-permissions: no permission prompts, Claude executes whatever a message asks for — shell commands, file edits, network access, git push, gh calls.
  • Everything runs with the rights of the system user that runs the bot and with that user's gh token.
  • Anyone in ALLOWED_USER_IDS (or who takes over such a Telegram account), and anyone who can influence the text Claude reads — repository files, issues, pull requests — can make the bot act as that user.
  • Isolate the process before you start it: a dedicated user without sudo, a narrow token, a container or VM.

Features

  • Sessions per chat

    Every chat or forum topic is its own Claude session that continues between messages.

  • Commit and push

    Clean-tree check and git pull --rebase before a run, commit and push after it, a commit link in the reply. Off with AUTO_COMMIT=0.

  • Queue, not rejection

    A request that arrives while the bot is busy waits in a queue.

  • Live progress

    The "Thinking..." message shows what Claude says and which tools it calls.

  • Files both ways

    Send files to Claude; files Claude puts into the outbox come back to the chat.

  • Modes and epics

    arch, review and pm modes with replaceable personas, 13 interface languages, and epics of tasks the bot drives to completion.

Epics: from an idea to merged pull requests

Besides chatting with a repository, the bot can carry a set of tasks to completion. Claude handles the steps that need judgement, the bot's Orchestrator handles the deterministic ones, an external executor writes the code, and the author keeps the decisions that must stay human.

  1. ArchitectClaude in the pm mode designs the change, runs it through cold critique, verification, editing and a scope check, and opens the issues.
  2. Authorre-reads the tasks and sends /epic start.
  3. Implementeropenronin writes the code and opens pull requests; independent tasks run in parallel.
  4. Reviewan optional cold CI review, then a hot review against the intent of the task and the epic plan.
  5. Mergethe Orchestrator merges, labels and releases, and stops a stuck epic.
  6. Final checkverifies the whole epic and writes the report for the author.

Epics rely on openronin as the external executor. Regular chat with the bot does not need it.

GitHub and GitLab

GitHub is the default. With FORGE=gitlab the bot works with gitlab.com or, with FORGE_HOST, a self-hosted instance, through the GitLab CLI glab. Minimum versions: GitLab 16.0 and glab 1.40.
